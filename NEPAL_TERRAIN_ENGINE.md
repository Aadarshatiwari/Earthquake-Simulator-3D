# Nepal terrain engine

The terrain opens from the archive’s **3D terrain** toggle. The renderer requests an offline 247 × 126 elevation grid only when the view opens. If that asset cannot be loaded or decoded, it tries the original 0.25° elevation grid. The UI distinguishes loading, rendering and a lost context, and offers the offline 2D map when 3D cannot be shown. A screenshot should be captured only after **Terrain rendered** and visually checked.

## Data and geometry

The 0.035° grid samples Mapzen’s zoom-7 Terrarium elevation tiles. The source documents SRTM as the land source at Nepal’s latitude and zoom level. Twelve tiles cover x=92–95 and y=52–54. Nearest tile pixels are decoded as metres with the Terrarium RGB formula and rounded to the nearest metre. The resulting sample spacing is approximately 3.4 km east–west and 3.9 km north–south near 28.4° N. This limits how much summit, valley and local slope detail can be resolved. The highest bundled grid sample is 7,819 m. [AWS registry](https://registry.opendata.aws/terrain-tiles/), [Tilezen source documentation](https://github.com/tilezen/joerd/blob/master/docs/data-sources.md), [terrain attribution](https://github.com/tilezen/joerd/blob/master/docs/attribution.md).

The indexed mesh uses approximate local kilometre coordinates centered at 84.1° E, 28.4° N with a constant longitude scale based on the centre latitude. The relief scale ranges from 1× to 8× and starts at 5×. It scales the vertical geometry only. Surface colours, snow tint and atmosphere are illustrative. Administrative mode shows generalized districts, cities and river lines. [Open Knowledge Nepal boundaries, CC BY 4.0](https://localboundries.oknp.org/), [Natural Earth rivers, public domain](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-rivers-lake-centerlines/).

The separate Geology layer displays 50 extracted surface-trace segments from the GEM Global Active Faults Database’s HimaTibetMap contribution, pinned at revision `850fd05`. Lines were cropped to contiguous source vertices in the relief footprint and rounded to four decimals. The derived data are distributed under CC BY-SA 4.0. The layer does not estimate rupture geometry or predict faults that will move. [GEM dataset](https://www.globalquakemodel.org/product/active-faults-database), [release attribution](public/archive/gem-active-faults.LICENSE.txt).

The hypocentre uses the catalogue depth below the displayed terrain reference. Real provider depth datums may differ. The west–east section samples elevation at the event latitude and shows modelled hypocentre depth, geographic span and separate diagram scaling. Unknown or out-of-grid source locations do not produce a depth marker. Published USGS ShakeMap contours are static colour-coded lines draped over the terrain with adjustable opacity.

## Rendering lifecycle

The saved Phase 4 frame was blank. The same checkpoint later rendered the original mesh in the same browser at a nonzero canvas size, with no WebGL errors recorded. The capture process had allowed the screenshot immediately after a UI toggle. A mounted canvas and toolbar were visible before mesh paint. A persistent camera, material or shader failure did not reproduce. The checkpoint screenshot’s original GPU timing cannot be reconstructed.

The renderer now uses the terrain mesh’s render callback and signals readiness on the following animation frame. Three-dimensional evidence was visually inspected after this signal. Explicit loading and fallback states cover asset failure, initialization failure, context loss and a render that does not arrive. Scene rendering is demand-driven. Geometry is indexed, reused as the vertical scale changes and disposed when replaced. The render loop invalidates frames during camera transitions, which respect reduced-motion preferences. Context loss and restoration handlers are installed and removed with the canvas. Hardware loss and restoration were not induced during browser testing.
